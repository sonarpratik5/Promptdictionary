## Acceptance criteria

| Area | Observable requirement |
| --- | --- |
| Discovery | Published prompts are discoverable; URL filters survive navigation; pagination has no duplicates; empty states recover. |
| Resource types | Prompts, harnesses, skills, workflows, and guides are distinguishable, searchable, versioned, and rendered with type-appropriate setup and limitations. |
| Adapt/copy/share | Substitution follows [architecture.md](architecture.md); stored templates stay unchanged; preview/copy match; failures are visible; links reopen exact declared values. |
| Contributions | Valid authenticated writes persist; invalid input is actionable; anonymous and non-owners cannot mutate. |
| Discussion | Authenticated users can comment/reply; revision context is visible; edits/deletes follow policy; unauthorized users cannot mutate; reports reach moderation. |
| Privacy/moderation | Unpublished rows are hidden from anonymous users; direct data access cannot bypass ownership/role rules; transitions are enforced. |
| User state | Bookmark/feedback retries do not duplicate rows and one user cannot alter another's state. |
| Content safety | Community content remains inert; no script execution, secret exposure, agent-instruction adoption, or automatic inference. |
| Evidence claims | Efficiency, accuracy, and unsupported-output claims show source, baseline, method, and limitations; unevaluated resources are labeled accordingly. |
| Coding-agent evaluations | Records bind to an exact resource/model/tool version and preserve fixture, expected/observed result, commands/checks, metrics, and reproducibility status. |
| Accessibility | Core flows work by keyboard at 360px, 768px, 1440px, and 200% zoom with labels, focus, and useful feedback. |
| Performance | Field p75 targets: LCP ≤2.5s, INP ≤200ms, CLS ≤0.1; record route, device/network, dataset, and method. |

## Verification approach

- **Unit (Vitest):** validation, filtering, substitution, and share-boundary edge cases.
- **Integration (isolated Supabase):** migrations, constraints, RLS, ownership, visibility, revisions, comment policy, moderation transitions, and idempotency using anonymous, owner, other-user, and moderator actors.
- **Browser (Playwright/manual):** browse → filter → resource → adapt → copy/share; auth → submit/revise/comment/reply/save/feedback; keyboard, mobile, zoom, reduced motion, clipboard failures, and recovery paths.
- Use synthetic data and never mutate production. Mocks do not prove database policies.
